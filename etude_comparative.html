VOC Project — Étude Comparative Détaillée des Outils

Analyse des solutions open-source pour la plateforme de gestion de vulnérabilités

Document Version:1.0
Date:June 2026
Auteur:Ben Lazreg Yassine, Yahya Gharsallah
Contexte:Architecture k3s pour VOC (Vulnerability Orchestration Center)

1. Introduction

Cette étude comparative évalue les outils open-source sélectionnés pour la plateforme VOC, dans le cadre d'une architecture conteneurisée (k3s) avec une contrainte de 16 Go de RAM. L'objectif est de justifier chaque choix technologique en fonction de critères objectifs : performance, intégration, coût et adéquation avec les besoins du projet.

2.3 Décision : Nuclei

Raisonnement

Nuclei est clairement supérieur pour une architecture conteneurisée avec 16 Go de RAM car :

1. Légèreté : S'exécute comme un Job éphémère sans consommation résiduelle
2. Fiabilité : Taux de faux positifs réduit, aligné avec l'objectif de priorisation
3. Flexibilité : Création de templates personnalisés pour des applications spécifiques
4. Intégration CI/CD : Conçu pour l'automatisation

8.3 Décision : Grafana + Prometheus

Raisonnement

1. Légèreté : Consomme moins d'1 Go de RAM, compatible avec la contrainte des 16 Go
2. Monitoring Kubernetes natif : kube-prometheus-stack déploie Prometheus, Grafana, Alertmanager et node-exporter en une commande
3. Dashboards personnalisables : Permet de construire les panels requis (MTTR, SLA, couverture scan, top assets, vulnérabilités par sévérité)
4. Alerting intégré : Alertmanager pour les alertes sur seuils (ex: SLA dépassé)
5. Complémentarité : DefectDojo gère les findings, Grafana visualise les métriques et KPIs opérationnels — les deux outils sont complémentaires, non concurrents

📝 Note d'implémentation

DefectDojo n'expose pas nativement de métriques Prometheus. Un exporter léger (script Python ou sidecar) sera développé pour exposer les métriques métier (findings ouverts par sévérité, MTTR, SLA, couverture scan) via le endpoint /metrics. Les métriques d'infrastructure (CPU, RAM, pods) sont fournies par node-exporter et kube-state-metrics inclus dans kube-prometheus-stack.

10. Conclusion

L'architecture retenue pour le VOC, basée sur k3s, est pleinement justifiée par cette étude comparative. Le choix de Nuclei, OWASP ZAP, Grype, DefectDojo, n8n, TheHive et Grafana + Prometheus constitue une pile technologique :

✅ Robuste : Outils éprouvés et mature
✅ Moderne : Architecture conteneurisée cloud-native
✅ Open-source : Entièrement gratuit, sans dépendance commerciale
✅ Adapté aux ressources : Fonctionne dans 16 Go de RAM
✅ Aligné avec les objectifs : Priorisation avancée des vulnérabilités

Cette sélection permet de construire une plateforme de gestion de vulnérabilités efficace, automatisée et évolutive, avec une supervision complète des KPIs opérationnels (MTTR, SLA, couverture des scans).
